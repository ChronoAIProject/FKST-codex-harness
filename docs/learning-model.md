# Learning Model — fkst-codex-harness

How the harness learns *which issues to engage*, *how to comment*, and *how to fix*
— and keeps improving. _As of 2026-06-30._

---

## 0. The core idea (there is no model training)

"Learning" here is **not** gradient training. It is three mechanisms working together:

1. **Memory** — example banks built from successful cases (the corpora in `data/`).
2. **Retrieval-conditioned generation** — at decision time a department retrieves the
   nearest successful examples and feeds them to `codex` (`spawn_codex_sync`) as few-shot
   context + guardrail rules. The model imitates what worked on *similar* cases.
3. **Feedback re-derivation** — `track` records what happened to *our* attempts; the
   `codex-learn` package periodically re-derives the banks/weights from history + our
   outcomes. The banks drift toward what actually earns traction for **us**.

**The corpora are the learning. Departments only retrieve from them. `codex-learn` is
the only thing that changes them.** No ML infra required — re-derivation is plain
computation (weight fitting, pattern induction, exemplar ranking) over JSONL.

---

## 1. The three loops

| Loop | Learns FROM | Stored AS (`data/`) | Applied BY | Feedback signal |
|---|---|---|---|---|
| **Selection** — which issues to engage | PR-linked wins vs `not_planned` losses + our outcomes | `area_rubric.json` (fitted weights + threshold) | `codex-triage/score_dedup` via `rubric.lua` | reply / invite / merge / ignored on our picks |
| **Engagement** — how to comment / participate | comment **threads** of merged issues (what earned the invite) | `corpus_engagement.jsonl` + `engagement_styleguide.md` | `codex-saga/dossier`+`engage` (retrieve top-k → few-shot) | maintainer reaction to *our* comments |
| **Implementation** — how to fix (PR) | closing-PR **diffs** + repo standards + H1–H5 | `corpus_pr_style.jsonl` + `pr_styleguide.md` + `codex-repo-structure.md` | `codex-saga/implement` (retrieve nearest diffs) | CI result + review comments + merge/reject on *our* PRs |

(We mostly **engage existing** issues; we **create** one only to consolidate a dedup
cluster with no canonical issue — same selection scorer decides.)

## 2. Memory artifacts (`data/`, regenerated by `codex-learn`)

| Artifact | Content |
|---|---|
| `area_rubric.json` | fitted feature weights (area_tier, type, anatomy, demand) + bin thresholds |
| `corpus_selection.jsonl` | labeled issues: win (PR-linked) / loss (`not_planned`) / our-outcome |
| `corpus_engagement.jsonl` | successful issue threads + outcome (the comment exemplar bank) |
| `engagement_styleguide.md` | induced rules: lead-with-repro, cite `file:line`, offer to implement, ask direction, ~200 words, AI-disclosure |
| `corpus_pr_style.jsonl` | merged-PR diffs + the repo standards (AGENTS.md/CONTRIBUTING/justfile/lint) |
| `pr_styleguide.md` | induced rules: size ≤3 files/≤200 LOC, fail-before/pass-after test, atomic, conventions |
| `codex-repo-structure.md` | area→crate map (e.g. `exec`→`codex-rs/exec`, `mcp`→`codex-mcp`) |
| `open_issue_clusters.json` | dedup map → `dedup_key` |

---

## 3. How `codex-learn/relearn` re-derives each (concrete, no ML)

- **Selection weights** — re-fit the feature weights to maximize win/loss separation
  (AUC) over `corpus_selection` + our outcomes. Method: coordinate-ascent / simple
  logistic fit. Accept only if AUC ≥ 0.70 and per-bin win-rate stays monotonic
  (the gate from `METHODOLOGY.md`). Writes `area_rubric.json`.
- **Engagement styleguide** — cluster the *moves* in successful threads (opening,
  the "offer to implement / ask direction" turn, length, tone), extract recurring
  structure into rules, and keep the highest-outcome comments as the exemplar bank.
  Writes `engagement_styleguide.md` + re-ranks `corpus_engagement.jsonl`.
- **PR styleguide** — extract conventions from merged diffs (size, test pattern, file
  layout, commit shape) + the repo standards; keep nearest-diff exemplars. Writes
  `pr_styleguide.md` + re-ranks `corpus_pr_style.jsonl`.
- **Advocate calibration** — `codex-learn/calibrate_advocate` compares the advocate's
  recorded verdict vs the actual outcome → adjusts strictness; promotes recurring
  *valid* objections into new selection/PR rules (applied earlier next cycle).

---

## 4. Retrieval at decision time (how a department "applies" learning)

Same lightweight similarity we used for clustering (TF-IDF over title+body, by
area/type), no embedding service required:

```
department (score_dedup | engage | implement):
  1. similarity-rank the relevant corpus vs the target issue (area/type/text)
  2. take top-k exemplars (+ the styleguide rules)
  3. spawn_codex_sync(prompt = task + exemplars + rules)   # imitate what worked
  4. [advocate] gate the output before it is used/posted
```

So `engage` literally says: *"comment on this issue the way these k contributors
successfully commented on similar issues; obey these rules."*

---

## 5. Outcomes & feedback (`codex-saga/track` → `outcomes` durable)

Per attempt, recorded as program-produced durable state (never hand-edited):

```
{ source_ref, picked_score, exemplars_used[],
  engagement_reaction: none|reply|positive|invited|refused,
  ci: pass|fail, review_comment_themes[],
  disposition: merged|closed|ignored | refused_consensus|refused_volume_cap|refused_policy|refused_security,
  advocate_verdict: pass|refuted, advocate_reason,
  consensus_angles: { alignment, blast_radius, devils-advocate }, deliberation_count }
```

`exemplars_used` enables credit assignment (which exemplars led to good outcomes →
rank them up). `advocate_verdict` vs `disposition` drives advocate calibration.

**Deliberation capture (§7):** the gate records every refusal here too, via
`core.deliberation` — the per-angle consensus/dissent verdicts (`consensus_angles`), the
judgment count (`deliberation_count`), and the refusal reason. The append is UNCONDITIONAL
(dry-run-safe) so the "N deliberated · advocate refused M" funnel is retrievable without a
GitHub write. A `refused_*` disposition is **outside** the resolved set (`merged|closed|
ignored`), so `is_resolved_outcome` skips it: a refusal is retrievable but never (mis)counted
as a win/loss — a refused pick has no real-world disposition to score against.

## 6. The 4-phase cycle

```
PHASE 0  bootstrap   codex-learn/relearn (first run): pull threads + diffs,
                     induce styleguides, fit weights → data/
PHASE 1  apply       triage(score) ▸ implement(retrieve diffs) ▸ engage(retrieve comments)
                     — each behind an [advocate] gate
PHASE 2  record      track → outcomes (durable): reaction · CI · review · disposition · advocate
PHASE 3  re-derive   codex-learn (scheduled): append our outcomes to the 3 corpora,
                     re-fit weights, re-induce styleguides, re-rank exemplars, calibrate advocate
        └──────────────────────────── loops back to PHASE 1 ────────────────────────────┘
```

## 7. Package mapping

| Concern | Lives in |
|---|---|
| retrieve + score | `codex-triage/score_dedup` + `libraries/rubric.lua` |
| retrieve + comment | `codex-saga/dossier`,`engage` + `libraries/precedent.lua` |
| retrieve + fix | `codex-saga/implement` + `libraries/precedent.lua`,`repo_map.lua` |
| record outcomes | `codex-saga/track` → durable `outcomes` |
| **re-derive the banks** | **`codex-learn/relearn`** (scheduled raiser) |
| calibrate the advocate | `codex-learn/calibrate_advocate` |
| the advocate (gate) | `libraries/advocate.lua` (wraps `consensus`) |

## 8. Bootstrap requirement (blocker)

We pulled issue **bodies** only. Loops 2 & 3 have **no corpus** until we pull:
- comment **threads** of the 614 (esp. 339 merged) → `corpus_engagement.jsonl`
- their closing-PR **diffs** + repo standards → `corpus_pr_style.jsonl`
- the area→crate map → `codex-repo-structure.md`

`corpus_selection` + `area_rubric.json` already exist (`worked_on_full.jsonl`,
`not_planned_full.jsonl`, the calibrated scorer).

---

## 9. Why it improves — and the guardrail

- **Ever-improving:** every attempt adds labeled data (selection), a new comment
  exemplar (engagement), and a new diff+review record (PR). `relearn` folds them in,
  so the harness optimizes toward what works *for us on this repo*, not just history.
- **Guardrail:** the **devil's advocate** is what stops the loop becoming an echo
  chamber — a loop that learns only from its own confident picks reinforces its own
  bias. The advocate injects dissent at every gate, and its verdict is itself
  calibrated against outcomes. Improvement is driven by **outcomes, not self-confidence**.
