# fkst-codex-harness — Spec

The exact spec for the `fkst-codex-harness` repo: structure, packages, config,
dependencies, and what's required to stand it up. Aligned to the locked decisions
in `repo-architecture.md` §0 (**packages live in this repo; no PRODUCT/HOST split**).

*Status: design. As of 2026-06-30. Data basis: `codex-contribution-playbook.md`,
`METHODOLOGY.md`, `pilot-results.md`.*

---

## 1. Purpose & constraints

An autonomous, locally-run harness that finds high-value `openai/codex` issues,
diagnoses + fixes them on a fork, and proposes them back **by invitation**.

| Constraint | Consequence |
|---|---|
| Codex is **invitation-only**; uninvited PRs are closed | upstream = **read + gated-propose**, never auto-write |
| 283/284 merged PRs from trusted contributors | optimize **invitation-rate + self-fix path**, not PR-count |
| "Importance" = fixed-by-linked-PR | candidate scoring keys on the fix-rate rubric |
| We **don't own** openai/codex | the **fork** is the only writable code surface |
| FKST = **capability-secured, local engine** | per-device `supervise`; gh/codex/git as metered boundaries |
| FKST doctrine: **state only from the program** | no committed state; durable + GitHub markers; small payloads |

The three repos (see `repo-architecture.md`): **fork** (code only) · **`fkst-codex-harness`**
(this repo — packages + config + data + saga state) · **`fkst-substrate`** (engine → BIN).

---

## 2. Repo layout (EXACT)

`fkst-codex-harness` is a **self-hosting Lua package repo**: it owns its packages in
top-level `packages/` and runs itself (`supervise`) against the codex target.

```
fkst-codex-harness/
  packages/                              # ← THE CODEX PACKAGES LIVE HERE
    codex-triage/
      core.lua                           #   shared pure logic (require-able)
      raisers/issues.lua                 #   poll openai/codex issues → raise codex_candidate
      departments/score_dedup/main.lua   #   apply rubric + clusters → attemptable
      locales/en.lua                     #   t(key) catalog
      fkst.toml                          #   kind = "package"
      tests/*_test.lua
    codex-saga/
      core.lua
      departments/diagnose/main.lua      #   reproduce + bisect + root-cause on the fork
      departments/dossier/main.lua       #   story (precedent) + demo branch push
      departments/gate/main.lua          #   consensus + invite-precondition + caps
      departments/engage/main.lua        #   gh issue/comment on openai/codex
      departments/open_pr/main.lua       #   gh pr create fork→upstream + CLA
      raisers/invite_watch.lua           #   poll issue for maintainer invite
      locales/en.lua
      fkst.toml                          #   kind = "package.composed", persistence_class = "saga",
                                         #   [event_deps] packages = ["codex-triage"]
      tests/*_test.lua
  libraries/                             # optional shared Lua libs (contract/workflow-style)
  data/                                  # seed corpus (read by source_ref, NOT inlined in payloads)
    area_rubric.json
    open_issue_clusters.json
    worked_on_full.jsonl
  .fkst-substrate-ref                    # PIN: engine source (fkst-substrate SHA/tag)
  fkst.workspace.toml                    # manifest workspace; pin fkst-packages ONLY if reusing trio
  fkst.lock                              # locks any external (trio) source
  .fkst/
    env.example                          # tracked config template (§4)
    env                                  # gitignored, per-device
    runtime/ durable/                    # gitignored engine scratch + state
  scripts/run.sh                         # from scaffold — delegates to host-run (no copy)
  scripts/check_repo.py                  # from scaffold
  .github/workflows/ci.yml               # from scaffold
  README.md  CLAUDE.md  LICENSE  .gitignore
  docs/                                  # this spec + findings/methodology/pilot
```

Scaffold files (`scripts/run.sh`, `scripts/check_repo.py`, `.github/workflows/ci.yml`,
`env.example`, `.fkst-substrate-ref`, `.gitignore`, `README.md`) are generated by
`fkst-framework init-package-repo` — do not hand-write them.

## 3. Packages

**`codex-triage`** (flat package) — the read/score side.
- `raisers/issues.lua`: polls `openai/codex` issues, raises `codex_candidate` with a
  **small payload** `{source_ref, dedup_key, schema, score}`.
- `departments/score_dedup`: applies the rubric (R1–R4) + clusters → marks `attemptable`.

**`codex-saga`** (composed package, `persistence_class = "saga"`, depends on `codex-triage`)
— the diagnose→propose side; uses `once(key, fn)` for idempotent saga steps.
- `diagnose` → `dossier` → `gate` → `engage` → `open_pr`; `invite_watch` raiser.

Both follow the package-repo contract: `core.lua` (pure shared logic), `departments/<d>/main.lua`
returning `M.spec` + global `pipeline(event)`, `raisers/<r>.lua` returning a source
declaration, `locales/en.lua`, `tests/*_test.lua`.

## 4. Config (`.fkst/env`, two-plane, per-device)

```sh
# targets — keep the two "upstreams" distinct (don't collide with the devloop's
# FKST_DEVLOOP_UPSTREAM_BRANCH, which means a rollup branch)
FKST_CONTRIB_TARGET=openai/codex            # foreign: read + gated propose
FKST_GITHUB_REPO=ChronoAIProject/codex      # owned fork: write (branches/PRs)
FKST_FORK_LOCAL_PATH=/abs/path/to/codex     # local fork clone for worktrees
FKST_GITHUB_BOT_LOGIN=<device-bot>          # device identity (= gh login)
FKST_FORK_SYNC_BRANCH=main                  # ff openai/codex main → fork main

# gate policy
FKST_PROPOSE_REQUIRE_INVITE=1               # no upstream PR without a recorded invite
FKST_PROPOSE_DAILY_CAP=3                    # volume cap on new upstream engagements
FKST_PROPOSE_DISCLOSE_AI=1

# engine/runtime (substrate scaffold): BIN, FKST_RUNTIME_ROOT, FKST_DURABLE_ROOT (mandatory,
# fail-closed), FKST_RATE_POOL_ROOT, FKST_CODEX_PERMIT_SLOTS, retry knobs
BIN=/abs/path/to/fkst-substrate/target/debug/fkst-framework
```

## 5. The saga (departments · raisers · queues)

One **control issue per candidate on this repo's tracker**; state transitions are
program-produced (labels/markers), never hand-edited.

```
[raiser] codex-triage/issues       poll openai/codex ─► raise codex_candidate {source_ref,dedup_key,schema,score}
            ▼
[dept]  score_dedup                rubric + clusters ─► attemptable        (R1–R4; AUC 0.73)
            ▼
[dept]  diagnose                   sdk_git worktree on fork + spawn_codex_sync:
                                   reproduce → git bisect → root cause (file:line) ─► diagnosed
            │ not reproduced → needs_info (drop)
            ▼
[dept]  dossier                    story (precedent from worked_on corpus) + demo branch push
            ▼
[dept]  gate                       consensus + invite-precondition + volume-cap + AI-disclosure ─► cleared
            ▼
[dept]  engage                     gh issue/comment on openai/codex ─► engaged
            ▼
[raiser] invite_watch              poll issue for maintainer invite ─► invited
            ▼
[dept]  open_pr                    gh pr create fork→upstream + CLA ─► proposed → track to merge
```

Everything before `engage` is **local + read-only to the public**; `gate`, `engage`,
`open_pr` are the only outward actions.

## 6. State & payload model

- **Live state:** engine durable (redb) under `.fkst/durable` (gitignored). The
  **control issue** on this repo's tracker mirrors saga state on GitHub.
- **Payload discipline:** events carry only `{source_ref, schema, dedup_key, control}`;
  bodies/diffs/corpus are read back via `source_ref`.
- **`dedup_key`** ← `data/open_issue_clusters.json` (collapse duplicates to a representative).
- **`score`** ← rubric scoring (`METHODOLOGY.md` §5), calibrated AUC 0.730.
- **Seed corpus** in `data/`: `area_rubric.json`, `open_issue_clusters.json`, `worked_on_full.jsonl`.

---

## 7. What the engine reads / writes

| Target | Reads | Writes |
|---|---|---|
| this harness (project-root) | packages · config · seed data | runtime + durable **state** · saga **control issues** |
| `fkst-substrate` | — (it's the BIN) | — |
| `fkst-packages` (only if trio reused) | trio source (pinned) | — |
| **fork** | the codebase (worktrees) | **code fixes**: branches, commits, push |
| **openai/codex** | the issues (candidates) | **gated**: issue/comment + PR (by invitation) |

---

## 8. Dependencies & pins

- **Engine:** `fkst-substrate`, pinned by `.fkst-substrate-ref`, built locally to `BIN`.
- **Reused primitives (OPTIONAL):** `consensus`, `github-proxy` from `fkst-packages`,
  pinned via `fkst.workspace.toml` `[[external_sources]]` + `fkst.lock`. If we'd rather
  have zero external package dependency, these can be implemented in-harness instead.
- **codex CLI** on `PATH` (used by `spawn_codex_sync`).
- **`gh`** authenticated as the device bot (repo scope) for read/write/propose.

## 9. What is required to stand it up (checklist)

1. **Engine:** clone `fkst-substrate`, `cargo build`, note the `BIN` path; set `.fkst-substrate-ref`.
2. **Fork:** `gh repo fork openai/codex` → `ChronoAIProject/codex`; clone it locally
   (`FKST_FORK_LOCAL_PATH`); remotes `origin`=fork, `upstream`=openai/codex. (Fork Issues
   stay **disabled** — saga issues live on the harness, not the fork.)
3. **Harness repo:** create `fkst-codex-harness`; run `fkst-framework init-package-repo`
   to scaffold; author `packages/codex-triage` + `packages/codex-saga`; drop the seed
   corpus into `data/`; (optional) pin the trio in `fkst.workspace.toml` + `fkst.lock`.
   Issues **enabled** (default) — this is the saga tracker.
4. **codex CLI** installed and on `PATH`.
5. **gh auth** as the device bot with `repo` scope.
6. **Config:** copy `.fkst/env.example` → `.fkst/env`; set targets, `BIN`,
   `FKST_FORK_LOCAL_PATH`, stable `FKST_DURABLE_ROOT`/`FKST_RUNTIME_ROOT`/`FKST_RATE_POOL_ROOT`,
   gate policy, device identity.
7. **Run:** `scripts/run.sh test` (conformance + tests), then `scripts/run.sh supervise`.

---

## 10. Gates & safety

- **gate0** security/safety → `security@openai.com`, never public.
- **invitation precondition** → no upstream PR without a recorded maintainer invite.
- **consensus** → multi-angle approval before any foreign-plane write.
- **volume cap + AI disclosure** on every upstream post.
- **destructive remote ops** (close/force-push/delete) gated, per FKST doctrine.
- Engine changes → `fkst-substrate` only; behavior → this repo's packages.

## 11. Open decisions

1. **Gate model on the foreign plane** — consensus-only (unattended) vs a human
   checkpoint for the first N upstream engagements until the bot earns standing.
2. **Capability grant split** — distinct metered grants for "write to fork" vs
   "write to openai/codex" (host-side policy; likely no engine change).
